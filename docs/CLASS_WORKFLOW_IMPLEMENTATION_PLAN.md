## 첫 묶음의 구체적 설계

- 기존 운동 JSON은 보존한다. 세트 행 확장(`setRows`)에 목표·실제·완료를 저장하고 기존 kg/reps/sets 요약을 함께 유지한다. 옛 기록은 과거 상세 세트 값을 추측해 만들지 않고 ‘기존 요약’으로 표시한다.
- 2:1 출석·차감은 기존 함께 처리 정책을 유지하되 운동 기록은 회원별로 분리한다. 지난 수행은 현재 수업 이전의 해당 회원 기록으로 가져온다.
- 서버 초안은 회원×수업별 버전으로 CAS 저장한다. 변경 후 700ms 자동 저장, 저장 중/저장됨/실패/충돌을 표시한다. 새로고침은 마지막 서버 저장본과 지원 브라우저의 같은 탭 임시 입력을 복구한다. 탭 임시 입력은 trainer×session별 `sessionStorage`에 최대 12시간 범위로 보관하고 로그인/로그아웃·회원 영역 전환 시 제거한다. **탭 종료 뒤 미전송 입력 복원·완전 오프라인 동기화·기기 간 자동 병합은 보장하지 않는다.** 브라우저 저장이 막히면 복구 제한 안내를 보여준다.
- 완료와 정정은 세션 잠금·회원권 잠금·상태 버전·요청 UUID를 사용하는 DB RPC로 처리한다. 서버 액션과 RPC 모두 담당/대표 권한을 확인한다. 기존 취소 요청 RPC와 출석 원장을 연결하고 정정 후 기존 원장 행을 삭제하지 않는다.
- 출석은 회원 서명 필수·수업 당일부터, 회차 없음/정지·취소 정책은 서버가 판단한다. 수업 마감에서 기록을 먼저 저장하고 서명·차감 결과를 확인하며, 실패를 완료로 표시하지 않는다.
- 예약은 현재 고정 60분 충돌 검사와 이동 RPC 재검사가 있다. 예약 hold는 없다. 이번에는 이를 새 예약 상품으로 바꾸지 않고, 회차 표시를 ‘출석 시 차감되는 잔여’로 정확히 설명한다. 차감의 마지막 회차 경쟁과 정정/취소 경합은 첫 묶음에서 검증한다.
- 비파괴 SQL만 준비한다. 기존 행 삭제·운영 데이터 재작성·운영 마이그레이션 적용은 하지 않는다. 필수 마이그레이션 미적용 시 예전 비원자 경로로 조용히 돌아가지 않고 오류로 안내한다.

## 실행 방법·남은 경계

1. 로컬/테스트 Supabase에서 기존 마이그레이션에 이어 `0027_class_workflow.sql`을 검토·적용해야 실제 수업 경로가 동작한다. **이 작업에서는 어떤 운영 DB에도 적용하지 않았다.** SQL 적용 전 새 화면은 명확한 데이터 로드/저장 오류로 실패하고 예전 비원자 경로로 돌아가지 않는다.
2. 테스트 환경을 설정한 뒤 기존 `bun run dev` → `/t/record/[sessionId]`. 합성 UI만 보려면 개발 모드 `/dev/class-workflow`를 사용한다. production에서 이 fixture는 사용할 수 없다.
3. 기본 검증: `bunx tsc --noEmit`, `bun run lint`, `bun test`.
4. SQL 시험 도구는 프로젝트 의존성을 바꾸지 않도록 `/tmp`에만 설치했다. 재현 예:

```sh
npm install --prefix /tmp/season-pt-qa --ignore-scripts --no-audit --no-fund @electric-sql/pglite
PGLITE_MODULE_PATH=/tmp/season-pt-qa/node_modules/@electric-sql/pglite/dist/index.js node --test scripts/qa/class-workflow-db.mjs
```

5. UI 스크립트는 `http://127.0.0.1:3097/dev/class-workflow`의 개발 서버를 대상으로 한다. 설치된 Playwright 모듈을 `PLAYWRIGHT_MODULE_PATH`, 호환 Chromium 경로를 필요 시 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정해 `node scripts/qa/class-workflow-ui.mjs`를 실행한다. 이번에는 기존 도구/브라우저를 재사용했다. 실제 계정/운영 서비스를 시험 대상으로 지정하지 않는다.

**복구 제한:** sessionStorage를 지원하는 같은 탭의 임시 입력과 마지막 서버 초안만 복구한다. 탭 종료·OS 강제 종료 뒤 미전송 입력은 보장하지 않는다. 브라우저가 unload 경고를 생략할 수도 있다. 앱 뒤로 버튼은 미저장 경고를 제공하지만 브라우저 자체의 SPA 뒤로 동작을 강제로 차단하지 않으며 같은 탭 임시 복구에 의존한다. 다른 기기/탭 충돌은 자동 병합하지 않는다. 충돌한 입력은 보존하고 명시적인 폐기/서버 기록 확인을 요구한다.

**예약/후속 범위:** 기존 고정 60분 겹침 규칙을 유지하고 경계 시험을 추가했다. 미래 4주 예정 슬롯의 회차 hold·예약 중/사용 가능 회차의 원장 분리는 순서 2이며 이번에 도입하지 않았다. UI는 현재 잔여를 출석 때 차감한다고 설명한다. 결제·환불·정산 전체 원자화, 프로그램 배정, 외부 알림은 별도 후속 범위다.

**변경 배포/되돌림 전 확인:** 운영 적용을 결정한다면 먼저 별도 다중 연결 PostgreSQL 시험과 실제 인증 흐름 시험이 필요하다. 새 정정은 기존 원장을 보존하므로 새 정정 이력이 생긴 뒤 과거 ‘원장을 삭제하며 복원하는’ 서버 코드로 단순 롤백하면 안 된다. 데이터 삭제/역마이그레이션 대신 쓰기 제한과 호환 복원 계획을 검토한다. 이번에는 배포·롤백 작업을 실행하지 않았다.

최종 상태: 임시 개발/production smoke 서버 종료. 테스트 도구와 환경 없는 검증 복사본은 `/tmp/season-pt-qa`, `/tmp/season-pt-ui`에 있다. 운영 서비스에 연결된 작업이나 결과가 불확실한 DB 쓰기는 없다. 실제 프로젝트의 패키지 의존성·배포 설정·환경 파일은 변경하지 않았고, 커밋/푸시는 하지 않았다.
