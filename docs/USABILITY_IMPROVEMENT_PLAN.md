# 계절 PT & 필라테스 — 사용성 만점 달성 개선 방안서

> **목적:** 트레이너/회원 앱(모바일)과 대표 운영 콘솔(PC)의 사용성을 역할별(대표·강사·회원)로 평가하고, 만점 앱으로 도달하기 위한 구체적 개선 방안을 정리한다.
> **기반:** `docs/DESIGN_SPEC.md` 구현 명세 + 현재 코드베이스(`src/app/(app)/*`, `src/app/console/*`, `src/components/*`) 실사.
> **고정 제약 (변경 금지):**
> 1. 회원 초기/로그인 비밀번호 = **생년월일 6자리(YYMMDD)** 고정.
> 2. 회원 탈퇴 = **셀프 불가(선생님 문의)** 고정.
>
> 본 문서의 모든 방안은 위 두 제약을 전제로 하며, 보안/자기결정권 관련 대안은 별도 인증 수단으로 보완한다.

## 0. 현재 상태 요약 (평가 스냅샷)

| 영역 | 대표 (PC `/console` + 모바일 `/t`) | 강사 (모바일 `/t`) | 회원 (모바일 `/m`) |
|---|---|---|---|
| 진입·탐색 | ⭐⭐⭐⭐ UA 자동분기·사이드바 그룹 우수 | ⭐⭐⭐⭐ 캘린더 홈 적합 | ⭐⭐⭐⭐⭐ 마찰 최소 로그인 |
| 핵심 태스크 | ⭐⭐⭐⭐ 대시보드 투두 우수 | ⭐⭐⭐⭐⭐ 출석 처리 모범 | ⭐⭐⭐⭐ 일정 조율 흐름 양호 |
| 피드백·안전망 | ⭐⭐⭐⭐ 정산 stale·매출가리기 | ⭐⭐⭐⭐ 차감 미리보기·서명 | ⭐⭐⭐ 확정 화면·요청 상태 부족 |
| 정보 투명성 | ⭐⭐⭐⭐ 재무 전망 풍부 | ⭐⭐ **본인 정산/급여 불가** | ⭐⭐⭐ 잔여/D-day 명확, 결제 셀프 불가 |
| 일관성·중복 | ⭐⭐ **PC·모바일 기능 분산** | ⭐⭐⭐⭐ 권한 경계 정중 | ⭐⭐⭐⭐ 단일 목적 집중 |
| 접근성·가독 | ⭐⭐⭐ 좁은 화면 대응 약함 | ⭐⭐⭐ 아이콘 밀집·소텍스트 | ⭐⭐⭐⭐ 정보 밀도 적절 |

**최우선 3개 과제(만점까지 가장 큰 갭):**
1. 강사 본인 예상 정산액 노출 (투명성 2점 → 5점)
2. 회원 수신 화면 다중 요청 처리 + 요청 상태 표시 (피드백 3점 → 5점)
3. 대표 PC·모바일 기능 중복 정리 (일관성 2점 → 5점)

## 1. 개선 설계 원칙

1. **1화면 1주요액션 유지** — `DESIGN_SPEC` 원칙을 신규 화면에도 그대로 적용. 드릴다운은 `go()`(히스토리 push)/`back()`(pop) 그래프 안에서만.
2. **고위험 액션은 실행 전 결과 명시** — 출석 차감 미리보기(`t/attend/[id]/ui.tsx`) 패턴을 정산 확정·결제·회원권 변경에도 확장.
3. **현장 고려 디테일 확장** — 매출 가리기(`console/privacy.tsx`)·세션 슬라이딩 연장(`middleware.ts`) 수준의 고민을 모든 민감 화면에.
4. **권한 경계는 차단이 아닌 안내** — 강사 설정 진입 "대표만 가능" 배너(`t/settings/ui.tsx`) 패턴 준수.
5. **제약 내 보완** — 생년월일 비밀번호·탈퇴 셀프 불가를 유지하되, 결제 등 추가 인증이 필요한 곳은 **별도 결제 PIN / 간편결제 본인인증**으로 보완.
6. **데이터 기반** — 모든 폴링/realtime은 가시성 기반 중단·재개(`usePolling.ts` 패턴)를 따르고, 실패 시 조용히 마지막 값 유지.

## 2. 역할별 개선 방안

### 2.1 대표 (PC 콘솔 `/console` + 모바일 `/t/perf`)

#### A-1. PC·모바일 기능 중복·분산 정리  【P0】
- **현황:** 회원 관리가 `/console/members`(`console/members/ui.tsx`)와 `/t/members/register`(`t/members/register/ui.tsx`) 양쪽에, 설정이 `/console/settings`와 `/t/settings` 양쪽에 존재. 대표가 "이 작업은 PC? 폰?"을 매번 기억해야 함.
- **문제:** 동일 데이터·유사 폼이 두 인터페이스에 중복 → 학습비용·불일치 리스크.
- **방안:**
  - **책임 매트릭스 정의** — 대표 전용 고위험/대량 작업(회원권 상품·강사 정산·손익·일괄 등록)은 PC 고정. 모바일은 '조회 + 빠른 단건 처리(출석·단건 회원 등록·재등록 안내)'로 한정.
  - **교차 딥링크** — 모바일 대표 화면의 전용 기능(상품·정산·손익)에 "PC 콘솔에서 관리" 안내 행; PC 해당 페이지에 "모바일에서 빠른 처리" 가이드.
  - **공유 액션 레이어** — `lib/data/groups/*-actions.ts`는 이미 공유됨을 확인하고, UI만 역할-디바이스에 맞게 분기(중복 비즈니스 로직 방지).
- **구현 힌트:** `components/console/Sidebar.tsx` 그룹에 역할 배지 추가; `t/perf/page.tsx` ActionRow에 PC 전용 표시 칩.
- **완료 기준:** 대표가 어떤 작업을 어디서 해야 할지 매트릭스 1장으로 합의되고, 코드에 중복 폼이 단일 액션 레이어 위로 수렴.

#### A-2. 전역 검색 도입  【P1】
- **현황:** 회원·요청·메시지 각 섹션에만 검색박스. "박서연"을 한 번에 찾으려면 세 곳 왕복.
- **문제:** 대표의 가장 흔한 작업(특정 회원/요청 찾기)의 탐색 비용이 높음.
- **방안:** `Topbar.tsx`에 통합 검색 입력 → 엔터 시 회원/요청/메시지/강사 통합 결과 드롭다운(타입별 그룹핑, 키보드 화살표 선택). 서버 액션 `searchAll(q)` 신규(`lib/data/groups/console-actions.ts`).
- **완료 기준:** 헤더에서 한 입력으로 회원·요청·메시지·강사 4종 검색 결과가 200ms 이내 그룹핑 노출, 키보드로 선택 이동 가능.

#### A-3. 콘솔 반응형 처리  【P1】
- **현황:** 사이드바 248px 고정(`Sidebar.tsx`), 주간 그리드 7컬럼(`console/calendar/WeekGrid.tsx`). 좁은 노트북/태블릿에서 본문 빠듯.
- **문제:** 1280px 이하 디바이스에서 가로 스크롤·정보 잘림.
- **방안:**
  - `≤1280px`: 사이드바 아이콘 전용 모드(라벨 토글, 64px폭) + 툴팁.
  - 주간 그리드: 좁은 폭에서 시각 라벨을 1시간 간격에서 2시간 간격으로 축소, 블록 텍스트 생략 허용.
  - 콘텐츠 max-width 1200px 중앙 정렬(대시보드 이미 적용 중, 다른 페이지 확장).
- **완료 기준:** 1024px~1440px 구간에서 가로 스크롤 없음, 사이드바 아이콘 모드 자동 전환.

#### A-4. 미확정 정산 대시보드 알림  【P1】
- **현황:** 정산 'stale' 배너는 확정 **후** 출석 변경에만 동작(`settlement/ui.tsx`). 이번 달 정산을 **아직 확정 안 한** 상태는 대시보드에 노드가 없음.
- **문제:** 월 마감 누락 → 회계 오류 조용히 누적.
- **방안:** `console/page.tsx` todos 배열에 `if (!settlement.confirmed && 월 마감 임박)` 조건으로 "이번 달 정산 미확정" 투두 추가; 월별 `monthKey` 기준 확정 여부 조회(`getSettlement` 재사용). `t/perf/page.tsx` 모바일 대표 '오늘 할 일'에도 동일 항목.
- **완료 기준:** 매월 말일~초순 대시보드·모바일 대표 홈에 미확정 정산 투두가 자동 노출, 클릭 시 정산 페이지로 이동.

#### A-5. 주간 그리드 동시간 중복 수업 시각화  【P2】
- **현황:** 동일 시각 더블부킹 시 우측 8px 겹침 오프셋(`t/ui.tsx` `WeekBlock` dup). 렌더링 버그로 오해 가능.
- **문제:** 겹침이 '오류'로 인식되어 신뢰도 하락.
- **방안:** 겹침 슬롯에는 블록을 좌우 분할(각 50%)하거나, 겹침 시 블록 상단에 "×2" 뱃지 + 클릭 시 해당 시각 수업 목록 팝오버. PC·모바일 양쪽 `WeekGrid.tsx`/`t/ui.tsx` 통일.
- **완료 기준:** 동시간 2건 이상이 의도적 시각(분할 또는 카운트 뱃지)으로 표시되고, 클릭 시 전체 건 조회 가능.

#### A-6. 대표 다중 계정 / 역할 위임 (매니저 역할)  【P2】
- **현황:** 최초 1회 대표 가입 후 추가 대표/운영자 생성 경로 없음(`login/trainer/page.tsx` 부트스트랩).
- **문제:** 다인 운영 스튜디오(공동대표·매니저)에서 단일 대표 계정 공유 위험.
- **방안:** `trainers.role`에 `manager` 추가(대표 권한의 부분집합: 회원·캘린더·요청 O, 정산·손익·상품 X). 대표가 콘솔 강사 페이지에서 매니저 지정. 미들웨어·가드(`lib/auth/guard.ts`)에 역할 게이트 추가.
- **완료 기준:** 대표가 매니저 계정을 발급·권한 범위 설정 가능, 매니저 로그인 시 허용 메뉴만 사이드바 노출.

### 2.2 강사 (모바일 `/t`)

#### B-1. 본인 예상 정산액 노출 (읽기 전용)  【P0】
- **현황:** `/t/stats`(`t/stats/page.tsx`)는 수업 횟수·담당 회원·노쇼만 표시, **금액/정산 정보 전무**. 정산은 `/console/settlement` 대표 전용(`settlement.ts` `getSettlement`가 `role !== "owner"` 조기 리턴).
- **문제:** 강사의 가장 큰 관심사(내 수입)가 투명하지 않음 → 신뢰·동기 저하.
- **방안:**
  - 신규 `getMySettlementPreview()`(`lib/data/groups/settlement.ts` 또는 `trainer-home.ts`) — 로그인 강사 본인의 이번 달 attended 세션 × (스냅샷 `pay_rate` 우선, 폴백 `rate_1on1/2on1`) 합산. **확정 여부·다른 강사 단가는 노출 금지**(본인 스코프만).
  - `/t/stats`에 "이번 달 예상 수입" 카드 추가(세리프 대형 금액 + "확정 전 예상액" 서브). 노쇼·취소는 미포함 안내.
  - `monthLabel`·회당 단가 변경 이력이 있으면 "진행 시점 단가 기준" 각주.
- **구현 힌트:** `getSettlement`의 본인 행 계산 로직을 공용 함수로 추출(`computeTrainerPayout(trainerId, sessions)`)하여 대표/강사 양쪽이 재사용.
- **완료 기준:** 강사가 `/t/stats`에서 본인 이번 달 예상 수입(1:1·2:1 회당 수×단가 합)을 확인 가능, 타 강사 금액 미노출, 확정 전 표시 명확.

#### B-2. 강사 '회원 등록 요청' 권한 위임  【P1】
- **현황:** 회원 등록·회원권 발급은 전부 대표 전용(`t/members/register/ui.tsx` `createMember` → owner-ops-actions). 대표 부재 시 워크인 회원 온보딩이 막힘.
- **문제:** 영업 시간 내 대표不在로 신규 회원 즉시 등록 불가 → 첫 수업 지연·이탈.
- **방안:**
  - 강사용 '회원 등록 요청' 폼(최소 필드: 이름·연락처·성별·담당=본인·정기 요일/시간) → 대표 인박스/알림으로 '승인 대기' 전송.
  - 대표는 `/console/requests` 또는 신규 '등록 요청' 탭에서 1탭 승인(회원권은 대표가 발급 또는 '나중에 발급').
  - 승인 전까지 강사는 '임시 회원'으로 캘린더에 표시(점선 카드), 출석은 회원권 발급 후 가능.
- **완료 기준:** 강사가 대표 없이 신규 회원 등록 요청을 보낼 수 있고, 대표가 1탭 승인 시 정식 회원 전환.

#### B-3. 헤더 아이콘 밀집 해소  【P1】
- **현황:** `t/ui.tsx` 헤더에 인박스(42px)·알림(42px)·설정(42px) 3개 나란히 오탭 위험, 화면 라벨 없음.
- **문제:** 380px 모바일 폭에서 3개 42px 버튼은 촘촘함, aria 라벨만 있어 초보자 오인.
- **방안:**
  - 인박스 + 알림을 **하나의 '알림 센터'**로 통합(탭: 조율/시스템) → 헤더는 2개 아이콘(알림센터·설정)로 축소, 여백 확대.
  - 또는 인박스는 '일정 조율' 탭/별도 진입으로 이동하고 헤더는 알림+설정 2개만.
- **완료 기준:** 헤더 아이콘 수 ≤ 2, 버튼 간 여백 ≥ 8px, 미확인 건이 하나의 배지로 통합 표시.

#### B-4. 인박스에서 '다른 시간 제안' 직접 진입  【P1】
- **현황:** 받은 변경 요청 수락 시 회원 제안 슬롯 그대로 적용. 강사가 대안 제안하려면 class 상세(`/t/class/[id]`)→`propose`로 우회.
- **문제:** 빈번한 협의 경로가 2단계 → 이탈·지연.
- **방안:** 인박스 카드(`t/inbox/ui.tsx`)에 '다른 시간 제안' 보조 버튼 추가 → 클릭 시 `loadProposeSlots` 기반 슬롯 피커 인라인 전개(별도 페이지 이동 없이). 제안 발송 후 요청 상태 '제안함'으로 전환.
- **완료 기준:** 인박스 카드에서 1탭으로 대안 시간 제안 가능, 페이지 이동 없음.

#### B-5. 채팅 실시간화 + 타이핑 표시  【P2】
- **현황:** 탭바 미읽음 5초 폴링(`TabBar.tsx` `pollChatUnread`), 방 내 메시지도 폴링 기반, 타이핑 표시 없음.
- **문제:** 활동 많은 스튜디오에서 최대 5초 지연 체감; 타이핑 상태 없어 '답장 중인가?' 불확실.
- **방안:**
  - Supabase Realtime `postgres_changes`(chat_messages INSERT) 구독 → 새 메시지 즉시 렌더·미읽음 배지 갱신(폴링은 폴백 유지).
  - 타이핑 표시: 별도 경량 채널(presence 또는 임시 row)로 '입력 중' 표시, 3초 idle 후 소멸.
  - 가시성 기반 구독 해제(`usePolling` 패턴 확장).
- **완료 기준:** 새 메시지 1초 이내 화면 반영, 상대 타이핑 시 인디케이터 노출, 백그라운드 시 구독 중단.

#### B-6. 4번 탭 라벨 역할별 통일  【P2】
- **현황:** `trainerTabs`(`components/trainer/tabs.ts`)에서 대표='운영', 강사='내 현황'으로 4번 탭 라벨이 역할별로 바뀜. 계정 전환 시 미혹.
- **방안:** 4번 탭 라벨을 **'현황'**으로 통일, 내부 콘텐츠만 권한별 분기(대표: 스튜디오 전체 KPI + 투두; 강사: 본인 통계 + B-1 예상 수입). 탭 아이콘도 동일(`chart`/`chart-fill`).
- **완료 기준:** 대표·강사 전환 시 4번 탭 라벨·아이콘 동일, 내용만 권한 차이.

#### B-7. 주간 블록 가독성  【P2】
- **현황:** 주간 블록 텍스트 10.5px(`t/ui.tsx` `WeekBlock`), 정보 밀도는 좋으나 고시력 사용자에겐 작음.
- **방안:** 블록 내 텍스트 11.5px로 상향, 이름은 2줄 line-clamp 허용, 시각은 블록 상단 고정. 380px 폭에서 1시간 블록 높이(`HOUR_PX`)를 6px 증가시켜 여백 확보(스크롤 범위는 유지).
- **완료 기준:** 주간 블록 텍스트가 11.5px 이상, 이름·시각 모두 잘림 없이 표시.

### 2.3 회원 (모바일 `/m`)

#### C-1. 셀프 결제 / 재등록 (간편결제 + 별도 인증)  【P0】
- **현황:** 마이페이지 재등록 버튼이 토스트("선생님에게 메시지로 문의")로 종료(`m/my/ui.tsx`). PG 연동 없음.
- **제약:** 생년월일 6자리 비밀번호는 **고정** → 결제 인증을 이 비밀번호에 의존하면 보안 부족.
- **문제:** 회원이 온라인으로 즉시 결제 못 함 → 재등록 전환 손실; 대표 리텐션 관리가 보완하나 회원 측 자발성 낮음.
- **방안:**
  - **간편결제 연동** (토스페이먼츠/카카오페이 등) — 회원권 상품 목록 선택 → 결제 → 성공 시 회원권 자동 발급·결제 내역 기록.
  - **결제 전용 인증** — 결제 시 **생년월일 6자리 재확인 + (선택) 결제 PIN 4자리** 또는 간편결제사 본인인증. 회원가입 시 결제 PIN 설정 옵션(마이페이지 변경 가능). 생년월일 비밀번호 자체는 변경 금지 제약 유지.
  - 만료 임박 배너(`m/ui.tsx`)에 "지금 결제하기" CTA 추가.
  - 결제 금액 노출 정책은 대표가 설정에서 토글(일부 스튜디오는 가격 비공개).
- **구현 힌트:** 신규 `/m/my/purchase` 플로우; 서버 액션 `purchaseMembership(productId, method)`(`lib/data/groups/member-actions.ts`); 결제 내역은 기존 `payments` 테이블 재사용.
- **완료 기준:** 회원이 앱 내에서 상품 선택→결제→회원권 발급까지 셀프 완료, 결제 시 별도 인증 수행, 생년월일 비밀번호 정책은 불변.

#### C-2. 수신 화면 다중 요청 처리  【P0】
- **현황:** `m/receive/page.tsx` → `getMemberReceive()`가 **한 건만** 반환, `getMemberReceiveMeta()` 단일 `requestId`. 여러 요청이 동시에 와도 한 건만 노출.
- **문제:** 동시 도착한 나머지 요청을 회원이 인지 못 함 → 응답 누락·선생님과 일정 꼬임.
- **방안:**
  - `getMemberReceive`를 복수 반환(`MemberReceiveView[]`)으로 변경; UI는 목록 뷰(카드 스택) + 상단 "받은 요청 N건" 카운트.
  - 각 카드는 독립 수락/거절; 처리 후 목록에서 제거(남은 건 수 갱신).
  - 캘린더 홈 배너("선생님이 일정 변경을 요청했어요") 라벨에 "N건" 반영.
- **완료 기준:** 2건 이상 동시 요청 시 모두 목록 노출, 건별 처리 가능, 홈 배너에 건수 표시.

#### C-3. 요청 상태 표시 (대기/확인/수락/거절)  【P0】
- **현황:** 요청 발송 후 "요청을 보냈어요" 토스트만(`m/request/ui.tsx`), 이후 상태(선생님 확인 여부)를 회원이 알 수 없음.
- **문제:** "읽었을까?" 불안 → 재발송·중복 요청·이탈.
- **방안:**
  - `schedule_change_requests`에 `trainer_seen_at` 필드 추가; 회원이 보낸 요청 목록 신규(`/m/my/requests` 또는 캘린더 하단 '보낸 요청') — 상태 칩: 대기/확인/수락/거절/만료.
  - 선생님이 인박스 열면 `trainer_seen_at` 기록 → 회원 화면 '확인'으로 전환.
  - 푸시/알림톡으로 상태 변경 시 회원 알림(`notifications` 테이블 재사용).
- **완료 기준:** 회원이 보낸 요청의 현재 상태를 앱에서 확인 가능, '확인' 전환 시 알림 수신.

#### C-4. 요청 14일 한계 안내 + 장기 문의 경로  【P1】
- **현황:** `m/request/ui.tsx` 날짜칩이 오늘~13일 후(14개). 3주 뒤 일정 변경 요청 불가. 24h 무료 규칙 정책일 수 있으나 안내 부족.
- **문제:** 장기 계획 회원이 한계를 몰라 좌절.
- **방안:**
  - 날짜칩 영역 하단에 "14일 이후 일정은 선생님께 채팅으로 문의해 주세요" 안내 배너.
  - 14일 이후 날짜를 직접 입력하려 하면 인라인 안내 + "채팅으로 문의" 버튼(`/m/chat` 딥링크, 선생님에게 자동 메시지 초안 "O월 O일 수업 변경 가능할까요?").
- **완료 기준:** 14일 한계가 사전 안내되고, 초과 일정은 채팅 경로로 자연스럽게 유도.

#### C-5. 요청 히스토리 / 보낸 요청 조회  【P1】
- **현황:** 회원은 보낸 요청 이력을 조회할 화면이 없음(강사 인박스엔 '보낸 요청' 탭이 있음 `t/inbox/ui.tsx`).
- **방안:** C-3 상태 표시와 함께 '보낸 요청' 목록(최근 30일) 제공 — 마이페이지 '내 활동' 메뉴에 "일정 요청 내역" 추가(`m/my/ui.tsx` MenuRow).
- **완료 기준:** 회원이 최근 보낸 일정 변경/취소 요청과 결과를 마이페이지에서 조회 가능.

#### C-6. 결제 내역·영수증 조회 강화  【P2】
- **현황:** `/m/my/payments` 존재하나 영수증 다운로드·결제 수단 표시 수준 미확정.
- **방안:** C-1 셀프 결제 도입과 연계 — 결제 내역 카드에 영수증 PDF 다운로드/저장, 결제 수단·승인번호 표시. 환불 정책 안내 링크.
- **완료 기준:** 회원이 결제 내역에서 영수증을 다운로드 가능, 결제 수단·승인 정보 표시.

## 3. 공통 횡단 개선 (모든 역할)

#### X-1. 접근성(A11y) 강화  【P1】
- **현황:** 아이콘 전용 버튼이 많고 aria-label은 있으나 일관성 점검 부족; 일부 텍스트 10.5px; 컬러 대비(placeholder `#B3AA9C` on `#FAF8F4`) WCAG AA 한계.
- **방안:**
  - 모든 `tappable` 버튼 터치 타겟 ≥ 44×44px 보장(현재 일부 42px).
  - 컬러 대비 검증: placeholder·muted 텍스트를 AA(4.5:1) 충족 토큰으로 조정(`DESIGN_SPEC` 토큰 내 대안색 매핑).
  - 포커스 링(visible focus) 일관 적용 — 키보드 탐색 지원.
  - 스크린리더: 동적 알림(토스트·배지 변화)을 `aria-live` 영역으로 전달(`Toast.tsx` 확인 후 확장).
- **완료 기준:** axe/Lighthouse 접근성 점수 ≥ 95, 키보드만으로 주요 플로우 완수 가능.

#### X-2. 오프라인·네트워크 에러 상태 처리  【P1】
- **현황:** 폴링 실패 시 조용히 마지막 값 유지(`TabBar.tsx`)는 양호하나, 서버 액션 실패는 토스트 일변도. 오프라인 전역 안내 없음.
- **방안:**
  - `online`/`offline` 이벤트 감지 → 상단 얇은 배너 "네트워크 연결을 확인해 주세요" + 재시도 버튼.
  - 서버 액션 타임아웃/오프라인 시 "잠시 후 다시 시도" + 자동 1회 재시도(useTransition 기반).
  - PWA 캐시 전략 점검 — 오프라인에서도 캘린더·잔여 조회 가능하도록(정적 셸 + 캐시된 데이터).
- **완료 기준:** 오프라인 시 명확한 안내, 재연결 시 자동 복구, 캐시된 기본 정보 조회 가능.

#### X-3. 빈 상태·로딩 일관성  【P2】
- **현황:** `EmptyState`·`ScreenSkeleton` 컴포넌트 존재하나 일관 적용 여부 편차.
- **방안:** 모든 리스트 화면에 (a) 로딩: 동일 스켈레톤, (b) 빈: 아이콘+제목+설명+다음 액션 CTA 패턴 통일(예: 회원 없음 → "회원 등록하기").
- **완료 기준:** 모든 리스트/상세 화면이 동일 로딩·빈 상태 패턴, 빈 상태마다 다음 액션 제안.

#### X-4. 알림(푸시/알림톡) 통합 인박스  【P2】
- **현황:** 회원 `/m/my/notifications`·강사 `/t/notifications`·콘솔 `BellMenu` 각각. 알림톡 발송은 설정에서.
- **방안:** 각 역할 알림을 '시스템 알림'과 '대화/요청 알림'으로 분류, 미확인 필터링·일괄 읽음 처리. 알림 설정(수신 채널별 토글)을 마이페이지/설정에서 통일 편집.
- **완료 기준:** 알림 인박스가 분류·필터·일괄읽음 지원, 수신 설정이 채널별 세분화.

#### X-5. 다국어·폰트 접근  【P3】
- **현황:** 한국어 해요체 고정(`DESIGN_SPEC`). 외국인 회원 대응 없음.
- **방안:** (장기) 영문/다국어 키 매핑 — 강사·대표는 한국어 고정, 회원만 언어 선택 옵션(다국어 스튜디오 고객 대상). Pretendard 유지.
- **완료 기준:** 회원 앱에 언어 선택(한/영), 주요 화면 번역 완료.
